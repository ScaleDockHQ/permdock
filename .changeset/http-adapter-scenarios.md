HTTP adapters hold up under real servers. A create or an update that moves a row into another tenant is now denied with `tenant-mismatch`, on the server and in snapshot clients. The kernel caches one instance per request and tenant, and every adapter resolves `tenant` again on each `protect` (RPC adapters from each procedure's input), so a global middleware no longer pins a tenantless instance. `assert` inside a Hono, tRPC or oRPC handler now answers with the same Problem Details or RPC error as a guard denial instead of a 500. The Node body bridge no longer reads a chunk ahead, so `express.json()` and multer mounted after `permdock()` see the whole body. Fastify keeps the app's own error handler for other errors; Elysia plugins from two factories no longer dedupe into one; Nest runs on `@nestjs/platform-fastify`. Every HTTP adapter takes `limits` and `pdp` (`protect` decides delegated permissions through `permdock/pdp`), `protect` takes `ProtectOptions`, tRPC and oRPC take `request`, and Nest's `permdockHandler({ path })` sets the controller path. `permdock/server` exports `problemFromError`. `withOtel` records timed spans and a duration histogram in seconds. The PDP cache key covers the tenant, actor and row and is bounded, and `where` on a delegated permission is partial. `@permdock/testing` adds `testHttpAdapter` and `verifySaasToken`.
