# 0046. better-supabase 0.15.1 is the catalog pin and skips the one-day release age; the example stack runs on the pin only

- Status: accepted; the catalog pin and exclude are superseded by 0047
- Date: 2026-10-25
- Supersedes: the catalog pin, exclude and `database.yml` matrix parts of 0045

## Context

better-supabase 0.15 renames its blocks, client and config groups (`bs` to `bsb`, `blocks.access` to `blocks.permissions`, `blocks.tenant` to `blocks.memberships`) and replaces `sql sync` and `sql upgrade` with `better-supabase upgrade`. 0.15.0 maps a block onto tables only, so the example's `memberships` block could not run over the `public.organization_memberships` view that PermDock owns. 0.15.1 maps a block onto a view and writes only the functions that read it.

better-supabase 0.15.1 reached npm at 08:38 UTC on 2026-10-25. The standard installs only versions older than `minimumReleaseAge` (1440 minutes in `pnpm-workspace.yaml`).

A 0.13 `better-supabase` cannot load a config in the 0.15 shape, and the committed SQL in `apps/examples/next-better-supabase` is generated by one release.

## Decision

- The catalog pins 0.15.1, and `minimumReleaseAgeExclude` lists `better-supabase@0.15.1`, that version only. `minimumReleaseAge` stays at 1440 and `trustPolicy: no-downgrade` still checks the release. The 0.13.0 entry of 0045 is gone; 0.13.0 is older than the release age.
- The peer floor stays `>=0.13.0`, and `better-supabase-floor` still aliases 0.13.0. `ci.yml` tests the provider and its integration tests on `0.13.0` and `0.15.1`.
- `database.yml` runs the example stack on the catalog pin only, with no matrix: `gen:check`, the pg-delta drift check, both doctors, pgTAP and the agent stack test.

## Consequences

Remove the exclude from 08:39 UTC on 2026-10-26. The example stack no longer runs on the peer floor; the floor keeps its provider, type and integration coverage in `ci.yml` and `tests/better-supabase/peer-floor.test.ts`. `tests/package/better-supabase-peer-range.test.ts` checks that `ci.yml` covers the floor and the pin, and that `database.yml` installs no other version.

## Alternatives considered

- Keep the example on 0.13 and run 0.15.1 through the codemod in CI: the example would teach names adopters can no longer install with the next release, and the drift check would never run on 0.15.
- Wait one day for the release age: CI would not test the version adopters can already install, and the example would wait a day on a fix made for it.
