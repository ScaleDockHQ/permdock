---
title: codemod
description: Rename the identifiers a permdock release renamed, in every file that imports permdock, rewrite the call shapes it can tie to an import, and list the rest for a manual edit.
---

`permdock codemod 0.5` applies the 0.5.0 renames to your source. It rewrites imports from `permdock` and `permdock/*` and every reference bound to them. Then it lists the sites it would not change on its own, each with `file:line:column`. It exits `0` whether or not it found anything; run your type checker afterwards.

## Usage

```bash
permdock codemod 0.5                      # every source file under the working directory
permdock codemod 0.5 src apps/web --dry-run # report only, write nothing
permdock codemod 0.5 src --json           # the report as JSON
```

The positional arguments after the version are files or directories; the default is the working directory. The command reads `.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs`, `.cjs`, `.vue` and `.svelte` files and skips `node_modules`, `dist`, `.git`, `.next`, `.turbo`, `.svelte-kit` and `coverage`. In a Vue or Svelte file it rewrites each `<script>` block. A file that imports no `permdock` entry is never changed, except a `permdock.config.*` file.

| Flag        | Meaning                                                                                                                  |
| ----------- | ------------------------------------------------------------------------------------------------------------------------ |
| `--dry-run` | Print the report without writing any file                                                                                |
| `--force`   | Rewrite files with uncommitted changes too; without it, a dirty file in a git work tree exits `3` (`dirty_worktree`)     |
| `--json`    | `data` in the envelope: `{ version, dryRun, scanned, files, followUps }`; an unknown version is RFC 9457 Problem Details |

The codemod rewrites files in place, so in [agent mode](/docs/cli/agent-mode) a run without `--dry-run` first asks for the person's consent (`rewrite`).

The version is `0.5`, `0.8` or `0.17` (`0.5.0` and `v0.5` are read the same way). Any other version is a usage error that names the supported ones, exit `2`.

## What it renames

The rename map is `packages/permdock/src/cli/codemod/renames-0.5.ts`; the [Naming](/docs/getting-started/naming#renamed-in-050) page lists every row. A row renames an identifier only where it is imported from one of the entries the row names, so a local `memorySink` of your own stays as it is.

| Source                                              | Result                                                                                                                                                  |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `import { memorySink } from 'permdock'`             | `import { memoryDecisionSink }`, and every reference to it renamed                                                                                      |
| `import { memorySink as sink } from 'permdock'`     | `import { memoryDecisionSink as sink }`; `sink` stays                                                                                                   |
| `import type { MemorySink }`, `{ type MemorySink }` | The type renamed the same way, in type positions too                                                                                                    |
| `const config = { memorySink }`                     | `{ memorySink: memoryDecisionSink }`, so the object keeps its shape                                                                                     |
| `export { memorySink }`                             | `export { memoryDecisionSink as memorySink }`, so your module's export keeps its name                                                                   |
| `export { memorySink } from 'permdock'`             | `export { memoryDecisionSink as memorySink } from 'permdock'`                                                                                           |
| `import * as pd from 'permdock'`, `pd.memorySink`   | `pd.memoryDecisionSink`                                                                                                                                 |
| `scimHandler({ store })`                            | `scimHandler({ directory: store })`: an option key in an object literal passed straight to the function the row names                                   |
| `const kit = createPermDock(…)`, `kit.permdock()`   | `kit.middleware()` from `permdock/hono`, `kit.getPermDock()` from `permdock/server`: a member on a module-level `const` that holds the factory's result |

A reference the import does not bind keeps its name: a parameter, a local variable, a destructured name, a property key or a member of another object. When the new name is already bound where a reference sits, or the file is a Vue or Svelte component whose template may read the import, the codemod writes `import { memoryDecisionSink as memorySink }` instead and leaves the references alone.

## What it rewrites

Some 0.5.0 changes move more than a name. The codemod rewrites these where the import binding shows the call is PermDock's; the rows live in `packages/permdock/src/cli/codemod/shapes-0.5.ts`.

| Source                                                                                                                                                           | Result                                                                                                                                 |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `<Protected fallback={…}>` from `permdock/react`, `react-native`, `solid`                                                                                        | `<Protected denied={…}>`                                                                                                               |
| `h(Protected, props, { fallback })` from `permdock/vue`                                                                                                          | `h(Protected, props, { denied: fallback })`                                                                                            |
| `<PermDockProvider defaults={{ fallback }}>`                                                                                                                     | `<PermDockProvider defaults={{ denied: fallback }}>`                                                                                   |
| `await createPermDock(policy, user, options)` from `permdock`                                                                                                    | `await getPermDock(policy, user, options)`, imported beside the others; any other core `createPermDock` call becomes `getPermDockSync` |
| `createPermDock` from `permdock/pdp`                                                                                                                             | `getPermDock`, which keeps its always-async behaviour                                                                                  |
| `customRoleSource({ rolesOf })`                                                                                                                                  | `customRoleSource({ rolesFor: rolesOf })`                                                                                              |
| `permdock.decideRoleChange(change)`, and `decideCredential`, `decideAutomation`, `decideSupportSession`, `whoCan` on any receiver                                | `decideRoleChange(permdock, change)`, imported from `permdock`                                                                         |
| `permdock.simulate({ arazzo, openapi })`                                                                                                                         | `simulateArazzo(permdock, { arazzo, openapi })`                                                                                        |
| `permdock.activate(input)` on a receiver named like `permdock` or a module-level factory result                                                                  | `activate(permdock, input)`                                                                                                            |
| `permittedIds(permdock, permission, scope)`, `mayUse(permdock, permission)`                                                                                      | `permdock.permittedIds(permission, scope)`, `permdock.mayUse(permission)`; the import goes once nothing reads it                       |
| `createPermDock(policy, user, { approvalPolicies: source })` from `permdock` or `permdock/pdp`                                                                   | `{ approvalPolicies: approvalPolicies(source) }`; a `memoryApprovalPolicySource([…])` value stays as it is                             |
| `createPermDock(policy, user, { policies: source })`                                                                                                             | `{ policies: hostedPolicies(source) }`                                                                                                 |
| `ttl: '30m'`, `after`, `per`, `window`, `maxDuration`, `duration` or a `durations` list of `s`, `m`, `h`, `d` or `w` strings, inside a call to a PermDock import | Whole seconds: `ttl: 1800`                                                                                                             |

## CLI calls

The same run rewrites `permdock` command lines renamed in 0.5.0 in `package.json`, `Makefile`, `justfile`, `Dockerfile`, `.yml`, `.yaml` and `.sh` files: moved commands (`permdock openapi` becomes `permdock openapi emit`), renamed flags and values (`usage --strict` becomes `usage --fail-on warning`, `catalog --format schema` becomes `catalog --kind json-schema`), and a changed default (`rls migrate` without `--write` or `--retire-out` gains `--dry-run`, since it now writes by default). It matches `permdock`, `npx permdock`, `pnpm exec permdock` and a versioned `permdock@0.4`, and stops a command at `&&`, `||`, `;`, a pipe, a redirect or a comment.

A flag that needs a person's choice is a follow-up, not a rewrite: `cloud push --environment` asks for the project id. In `.md` and `.mdx` files every call is a follow-up, since prose around it may need the same edit. The rows are on the [Naming](/docs/getting-started/naming#renamed-in-050) page.

## Config keys in 0.8

`permdock codemod 0.8` moves the `rls` keys 0.8.0 folded into named scopes. It edits the object passed to `defineConfig` and the default export of a `permdock.config.*` file; the rows live in `packages/permdock/src/cli/codemod/renames-0.8.ts`.

| Source                                                                                      | Result                                          |
| ------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| `rls.tenantType`                                                                            | `rls.scopeTypes.tenant`                         |
| `rls.teamType`                                                                              | `rls.scopeTypes.team`                           |
| `rls.memberships.tenant`, `rls.memberships.team`                                            | `rls.memberships.scopes.tenant`, `.scopes.team` |
| `tenant` and `team` on a table under `rls.memberships.scopes` or `rls.memberships.resource` | `columns.tenant`, `columns.team`                |

`tenant` and `team` stay valid keys there: they name the first and second declared scope. A key whose target is already set, or sits under a value that is not an object literal, is a follow-up to merge by hand. The options of `supabaseRls()` keep their shape; it normalises them itself.

The client `RolesOptions` lost `team` in 0.8. Every `useRoles` call (`permdock/react`, `react-native`, `vue`, `solid`) and every `roles` or `rolesFor` call in `permdock/svelte` is a follow-up: `useRoles({ team: id })` becomes `useRoles({ scope: "team", id })`, which lists only the roles on that team's memberships.

## Literals in 0.17

`permdock codemod 0.17` rewrites the object literals 0.17.0 reshaped, in `.ts`, `.tsx`, `.js` and `.jsx` files that mention `permdock`; the rows live in `packages/permdock/src/cli/codemod/shapes-0.17.ts`. It matches an object by its keys, not by the call it reaches, so run your type checker afterwards.

| Source                                                                 | Result                                                           |
| ---------------------------------------------------------------------- | ---------------------------------------------------------------- |
| `{ tenant: "acme", roles }`                                            | `{ scope: "tenant", id: "acme", roles }`                         |
| `{ tenant: "acme", team: "t1", roles }`                                | `{ within: { tenant: "acme" }, scope: "team", id: "t1", roles }` |
| `{ by, mode: "sequential" }`, `"all"`, `"any"` (with `by` or `stages`) | `{ by, combine: "sequential" }`                                  |
| `{ by, distinct: false }`                                              | `{ by, mode: "confirm" }`                                        |
| `{ by, distinct: true }`                                               | `{ by }`: `authorize` is the default                             |

A membership literal counts only when it has `roles`, `tenant` or `team` holds a string expression, and every key is a membership field (`via`, `expiresAt`, `grantedBy`, `reason`, `member`, `managedBy`, `entitlements`, `keep`, `eligible`, `x`). A credential, an event or a principal that carries `tenant` and `roles` stays as it is. A `distinct` that is not a literal and every `ApprovalMode` type reference are follow-ups: `ApprovalMode` is now `'confirm' | 'authorize'`, and the stage combinator type is `ApprovalCombine`.

## What it reports

These sites go under `Manual follow-ups` and are never rewritten:

- **Call shapes.** A call to an import whose signature changed, such as `subjectFromApiKey(options)(key)`, now `subjectFromApiKey(key, options)`. For `subjectFromApiKey` only the old shape counts: one argument that is an object literal or whose result is called. A call already in the new shape is left alone. An import of such a function that is never called is reported at the import.
- **Members.** A member renamed on a value a factory returns, when the value is not a module-level `const` holding the factory's result: a parameter, `const { permdock } = …`, or a value passed between modules.
- **Option keys.** An option key in an object literal that reaches a PermDock call, such as `{ source: 'mcp' }` for `call`. The object reaches the call when it is an argument of a function imported from the entry, or of a method on a value named after PermDock or held in a module constant from a PermDock factory, directly or nested in that argument's objects and arrays. An object passed to the application's own functions is left alone.
- **Unawaited core `createPermDock`.** A call returned or chained with `.then` without `await`. It still becomes `getPermDockSync`, which returns the instance; a source that answers asynchronously needs `getPermDock`.
- **Feature methods it cannot move.** An optional call such as `permdock?.whoCan(…)`, a call with type arguments, or one where the function name is already bound in that scope.
- **Approval policy options elsewhere.** An `approvalPolicies` key in an object literal that is not passed straight to `createPermDock`, `getPermDock` or `getPermDockSync`.
- **Duration strings elsewhere.** The same keys in an object literal that is not inside a call to a PermDock import, with the seconds to write.
- **Template slots.** A Vue `#fallback` slot or a Svelte `{#snippet fallback}` in a component that imports `Protected`, and a `PermDockProvider` whose `defaults` the codemod cannot read or whose import it cannot see.
- **Parse failures.** A file the parser rejects is listed and left as it is.

## Why

A rename that only a changelog describes costs every consumer the same search and replace, and a text replace renames a local `memorySink` or an object key along with the import. The codemod parses each file with `oxc-parser` and follows the import binding through its scopes, so it changes exactly the names PermDock exported. A call whose shape changed is rewritten only where the import binding or the call proves it is PermDock's; every other site is listed instead of guessed. The rename map is one TypeScript file that the changesets and the Naming page are checked against by `pnpm docs:drift`, so the three cannot drift apart.
