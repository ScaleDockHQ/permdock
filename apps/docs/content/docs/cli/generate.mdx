---
title: generate
description: Write the files each configured plugin emits from the policy, in one command.
---

`permdock generate` loads the policy, builds one model, and runs every plugin in `plugins`. A config with `plugins: []` is valid and writes no plugin files. `--check` writes nothing and exits 1 when a file would change or the policy is over a byte budget in [`budgets`](/docs/cli/bundle#budgets). The diff is on stdout, one `+` or `~` row per file. The receipt is on stderr.

`rls generate`, `supabase hook generate`, `powersync generate` and `scim generate` are not commands. `permdock generate --only <plugin>` writes that plugin. `permdock openapi emit` writes security into an existing document. `permdock codemod 0.26` rewrites `package.json` scripts.

## Usage

```bash
permdock generate
permdock generate --only rls --only powersync
permdock generate --check
permdock generate --dry-run
```

| Flag                | Meaning                                                                                        |
| ------------------- | ---------------------------------------------------------------------------------------------- |
| `--only <plugin>`   | Run this plugin. Repeat the flag to run more than one.                                         |
| `--check`           | Exit 1 when a file on disk differs or a budget is exceeded; write nothing. The diff is stdout. |
| `--dry-run`         | Report each change as `planned`, with its byte delta; write nothing.                           |
| `--policy <module>` | The module exporting the policy. Default: `policy` in the config.                              |
| `--no-cache`        | Emit and write even when a cache entry matches.                                                |
| `--cache-dir <dir>` | Cache directory. Default `node_modules/.cache/permdock`, or `PERMDOCK_CACHE_DIR`.              |
| `--concurrency <n>` | How many tasks run at once. `1` runs them one at a time.                                       |
| `--watch`           | Generate again when a policy, config or plugin input changes. Ctrl-C exits 130.                |
| `--db-url-stdin`    | Read the Postgres URL from stdin. RLS index suggestions and hook helper checks use it.         |
| `--local`           | Use the local Supabase stack's `DB_URL` from `supabase status` in place of stdin.              |
| `--stack <name>`    | With `--local`, the named stack of this worktree.                                              |

When a new seeds or defaults migration is due, the command prints `seeds: +N rows, -M rows against the newest seeds migration (<file>)` on stderr, counted by value row against the newest migration that carries the marker. The helpers carry a `sha-256:` digest on their first line ([PD115](/docs/cli/doctor#pd115-a-migration-behind-the-schema-file)).

`--json` puts `files` and `summary` in the result. Each file has `path`, `plugin`, `outcome`, `bytes` (size after the run) and `delta` (`bytes` minus the size on disk before; `bytes` for a new file). `--check` and `--dry-run` also print one stdout row per file that would change: `+ path (+N bytes, M total)` for a new file and `~ path (…)` for a changed one. `outcome` is `created`, `updated`, `unchanged` or, with `--dry-run`, `planned`. A cache hit leaves those files `unchanged` and counts them in `summary.skipped`. The stderr row is `Skipped (cache) N`. With `--watch`, each cycle is one JSON line on stdout and the process keeps running.

## Exported copies

Under pg-delta, `supabase db schema declarative generate` writes every object of the database to its own file, so PermDock's functions land in `permdock/functions/<name>.sql` and its policies inside `<schema>/tables/<table>.sql`, next to the files PermDock writes. `permdock generate` rewrites each such file without the `create function` or `create policy` of an object a plugin emits, together with the `alter function`, `comment on` and `grant` statements on that object in the same file. A grant on a PermDock function in a file without its `create` stays. The stderr notes name each copy: `removed the exported copy of permdock.permdock_user_id from supabase/schemas/permdock/functions/permdock_user_id.sql`. A file whose first line is a PermDock header, and the `_custom/` and `_cluster/` folders the export reserves, are never rewritten. A plugin `out` inside `_custom/` or `_cluster/` fails with `config_invalid`. [PD095](/docs/cli/doctor#pd095-schema-sql-pg-delta-cannot-diff) reports a copy that remains.

`--watch` loads the policy in a new worker on every cycle, because native ESM cannot drop a module it has already imported. A cycle writes nothing until the policy and the plugins have been read.

`pnpm generate:perf` records a cold run, a warm run, and a generate after a one-line policy edit on the CentraKit-size fixture. Peak RSS fails the gate at 10% above `scripts/generate-perf.json`. Wall time is printed and not enforced.

## Why

One command runs every plugin against the same model. Plugin order is the `plugins` array, then each plugin's `after` list.
