---
title: "0037: Policy generics through adapters"
description: Every createPermDock infers Policy TUser so consumers never cast a typed policy.
---

## Status

Accepted, September 2026.

## Context

`Policy` is generic over the user type that `definePolicy` `subject` accepts. Adapter factories took a bare `Policy` (that is, `Policy` of `unknown`). Function-property contravariance then rejected a typed policy, so examples and apps wrote `policy as Policy`.

## Decision

`createPermDock` in core and every adapter is generic over `TUser` and `TPrincipal`. The policy argument is `Policy<TUser, TPrincipal>`. Adapter `subject` options return `TUser` (or a thenable of it). A thrown resolver still becomes `null` and evaluates as anonymous.

`Policy.subject` and `Policy.context` are declared as methods so a typed policy remains assignable to helpers that only need roles and grants.

## Consequences

- Consumers pass `definePolicy` output to any adapter without a cast.
- Adapter `subject` callbacks are checked against the policy's user type.
- Internal helpers that take `Policy` keep compiling.

## Alternatives considered

- **Keep `policy as Policy` at the boundary.** Rejected: a public generic that consumers must erase is not an API.
- **Default `TUser` to `any`.** Rejected: it would silence real mismatches.
