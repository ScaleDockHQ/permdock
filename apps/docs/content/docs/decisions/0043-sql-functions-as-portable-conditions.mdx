---
title: "0043: SQL functions as portable conditions"
description: A `sqlFunction` condition names a Postgres function, carries a portable in-memory twin, and lets SQL-authority projects keep their RLS helpers while `can`, `where` and `verify` agree.
---

## Status

Accepted, September 2026.

## Context

`permdock rls` made the portable condition the single source: `generate` emits `CREATE POLICY`, `import` reads SQL back, `verify` proves `can()` and the database agree. That posture fights projects whose authority is a SQL catalog: declarative `supabase/schemas`, helper functions such as `job_permitted()`, and CI that must not `db push`. Importing those policies produced `opaque` nodes. An opaque condition evaluates to `false` in memory, so the TypeScript copy denied everything the function governed and the portable-condition benefit was lost.

The docs also promised more than the code shipped: `rls import` was regex-based with text fingerprints while `cli/rls.mdx` described `pgsql-parser` and AST fingerprints, and `rls verify --db` only ran in-process.

The missing primitive is a way to declare "in SQL this is a function call; in memory it is this portable condition; prove they agree" — the same shape as the dialect `memberships` mapping, generalised to named functions.

## Decision

1. **`sqlFunction(name, { args, twin })` is a portable condition node.** Wire shape `{ op: 'sqlFunction', name, args, twin }`. `name` is a SQL identifier or `schema.fn`. `args` are column `{ field }` refs or portable values. `twin` is a portable condition (no `opaque`, no nested `sqlFunction`, no closures). The evaluator and `compileWhere` run the twin. There is never a database or network call (invariant 15).
2. **`rls generate` emits the call.** Default SQL is `name(args)`. `--inline-functions` (or `rls.inlineFunctions`) emits the compiled twin instead, for engines that have no SQL functions. The database keeps owning the function body.
3. **`rls.functions` maps names for import.** `rls import` parses `USING` / `WITH CHECK` with `pgsql-parser`, fingerprints the deparsed AST, and turns a `FuncCall` whose name is in `rls.functions` into a `sqlFunction` node with that mapping's twin. Unmapped calls stay `opaque` and print `add rls.functions.<name>`. When `--db` is set, import also prints `pg_proc.prosrc`.
4. **Database-first is a supported posture.** SQL remains authority. Teams never have to run `generate`. They pin a TypeScript policy (with `sqlFunction` twins) to the live policies and run `permdock rls verify --db` in CI. `verify --db` uses the optional `pg` peer, compares `can()` on the twin with the database executing the real function, reports opaque grants as untestable app-side, and reports `sqlFunction` grants as verified through twin. Doctor `PD016` warns when an `rls` config has opaque grants or `sqlFunction` grants without fixtures.
5. **Unknown `sqlFunction` nodes deny on older readers.** The node is additive in the condition shape. A snapshot or decision event carrying it is portable (`portable` is not `false`). Readers that do not know the op fail closed on evaluation if they reject unknown ops; this repository's evaluator handles the node.
6. **PowerSync, Electric and Zero stay unscheduled** as generator targets over the same AST. Those engines have no SQL functions, so a later generator inlines the twin, the same way `--inline-functions` does for Postgres.

## Consequences

- SQL-authority apps can migrate without inverting their source of truth.
- Twin drift is a real threat: the function body and the twin can diverge. Mitigation is `verify --db` in CI and import fingerprints. The threat model records the row.
- PermDock Cloud must accept the new node in snapshots and decision events.
- `authorize('key')` remains a follow-up `sqlFunction` preset, not a new op.

## Alternatives considered

- **Keep opaque and tell SQL-first teams PermDock is TS-first.** Rejected: the portable-condition benefit is the product, and helper functions are the Supabase-recommended pattern.
- **Call the SQL function at runtime from `can()`.** Rejected: invariant 15, and it would not work on device or in `where` compilers.
- **Inline every function on import into portable AST.** Rejected: `CASE` and multi-join bodies do not round-trip; the function is the unit the DBA owns.
- **A closure that the author promises matches the SQL.** Rejected: closures are non-portable, skip RLS generate, and cannot snapshot or filter offline.
